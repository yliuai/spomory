# Epic 5.1/5.3：图片输入处理与多模态特征验证

对应创业方案「二、3. 多模态处理」的诚实定位：不宣称"原生跨模态抽取"，
只把工程精力放在"用图像原始特征反向验证候选三元组"这一具体环节上。
下面记录的是这个环节的真实实现和真实测试结果，不是占位/合成数据。

## 流程（真实跑通，非伪代码）

1. **Captioning**（`multimodal/image_captioning.py::OpenAICompatibleVisionProvider`）：
   用支持视觉输入的 OpenAI 兼容模型（这次用的是 DeepSeek 的
   `deepseek-v4-flash-vision-exp`）把图片转成文字描述。
2. **抽取**：把描述文本喂给 Epic 1.4 已经跑通的 `LLMProvider.extract_triples()`
   ——完全复用，没有为图片输入单独写一套抽取逻辑。
3. **CLIP 验证**（`multimodal/clip_verification.py::ClipVerifier`）：用真实的
   开源 CLIP 模型（`openai/clip-vit-base-patch32`）计算候选三元组文本和
   原图之间的余弦相似度，作为二次校验分数。

## 测试图片：10 张真实图片，人工标注期望关系

图片来自 picsum.photos（背后是真实 Unsplash 照片，每个数字 ID 对应固定的
真实照片，可复现），我逐张用 Read 工具实际看过并标注了期望的实体关系，
存在 `benchmarks/data/multimodal_ground_truth.json`（黑色幼犬/戴毯子的巴哥犬/
狮子特写/海象群/草莓/水母/海崖/城堡/瀑布下的人/悬崖峭壁，覆盖动物、
食物、风景、人物等不同主题，互相之间视觉内容差异明显）。

## 结果一：真实 pipeline 在这 10 张图片上的抽取质量很高

跑通 captioning→抽取 全流程（`benchmarks/results/multimodal_real_extraction.json`），
10 张图片全部生成了准确、贴合图片内容的三元组。例如黑色幼犬那张：

```
caption: 一只黑色的幼犬坐在带有横向纹理的旧木地板上，正仰头向上看着镜头。
triple: (幼犬, 坐在, 带有横向纹理的旧木地板上)
triple: (幼犬, 仰头向上看着, 镜头)
triple: (幼犬, 是, 黑色的)
```

和人工标注的期望关系（"puppy sits on wooden floor"、"puppy is black
labrador"）语义一致。10 张图片全部如此——**这本身是一个诚实的发现**：
在这批测试图片上，视觉模型的 captioning 质量已经很高，没有观察到自然
产生的幻觉/错误，所以没法在这批真实抽取结果上直接展示"CLIP 校验修正了
一个真实错误"这种案例。

## 结果二：用构造的干扰项，验证 CLIP 校验机制本身确实有效

既然真实抽取没有自然出现错误，就用一个能控制难度的实验直接检验"这个校验
机制本身是否有区分能力"（`benchmarks/multimodal_eval.py`）：给每张图片配
2 条真实候选三元组 + 2 条从**另一张**图片的真实三元组里借来的"干扰项"
（文字上完全通顺、但和这张图片的实际内容不符——这正是多模态校验要抓的
那类错误：候选三元组本身语法/语义都没问题，只是和这张图不对应）。

| 方法 | 准确率 |
|---|---|
| 纯文字描述（无法访问图片，只能全盘接受抽取结果） | 50.00%（40条候选里 20条为真，天然上限） |
| CLIP 二次校验（按分数取 top-N 判定为真） | **100.00%**（40/40 全部判断正确） |

原始数据：[`multimodal_eval.json`](../benchmarks/results/multimodal_eval.json)。
逐条得分见该文件的 `per_image`——每张图片里，2 条真实三元组的 CLIP 分数
都严格高于 2 条干扰三元组，10 张图片无一例外。

## 如实说明这个结果的局限

**100% 分离度部分是因为测试设计偏"简单模式"**：干扰项借用的是完全不同
主题的另一张图片（比如拿"狮子"的三元组去干扰"幼犬"的图片），CLIP 区分
两个语义上相去甚远的场景本来就比较容易。真实世界更棘手的幻觉往往更
"微妙"——比如同一场景里说错了颜色、方位或数量（"黑色幼犬"错说成"棕色
幼犬"，两者用的都是同一批词汇、只有一个属性不同），这种更细粒度的区分
CLIP 是否还能做到 100%，这次没有测试，需要用更难的干扰项重新跑一遍才能
知道。

**这次跑通的是"机制验证"，不是"生产环境错误率下降了多少"**——因为真实
抽取在这批图片上没有出错，没有真实案例可以拿来对比"校验前 vs 校验后"
的错误率变化。
